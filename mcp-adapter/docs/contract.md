# Tool contract v1.0

All four tools accept exactly `{}`. JSON Schema rejects additional properties.
No URL, file path, date, location, coordinates, or write-operation input exists.
All tools declare `readOnlyHint=true`, `destructiveHint=false`,
`idempotentHint=true`, `openWorldHint=true` (they read an external public service).
There are no other tools, resources, prompts or school-calendar operations.

| Tool | Fixed Pages suffix | `data.kind` | Purpose |
| --- | --- | --- | --- |
| `getDwmlForecast` | `/api/forecast.dwml` | `forecast` | Daily highs/lows, probabilities, conditions, worded forecast and icons |
| `getHourlyDwmlForecast` | `/api/hourly-forecast.dwml` | `forecast` | Hourly temperature, dew point, wind chill, PoP, wind speed/gust/direction, cloud, humidity, rainfall and conditions |
| `getAreaForecastDiscussion` | `/api/area-forecast-discussion.txt` | `discussion` | Extracted SGX product, sections, issuance |
| `getSnapshotStatus` | `/api/status.json` | `status` | Latest collection attempt and weather-only fetch/hash metadata |

Origin/base is compiled into `service.BASE`:
`https://st6npyj5hd-tl-9f3c2a7b1d5e4c08.github.io/5f8d3c9a1b7e4f20c6d2a9e8b14f73ab`.
Source URLs and XML URLs returned as evidence are never fetched by the adapter.

## Envelope

`docs/tools.json` is the full discovery contract, including recursive JSON
Schemas, generated by `uv run python scripts/export_contract.py`. CI detects drift.
Every successful MCP call contains identical JSON in `structuredContent` and a
text content block for client compatibility. Tool failures set MCP `isError=true`.

- `schema_version`: `1.0`.
- `status`: `ok`, `degraded` (data plus warnings), or `error` (no data).
- `provenance`: provider, fixed source URL, UTC retrieval timestamp, configured
  coordinates, timezone, `snapshot_not_live=true`, collection attempt, document
  generation, identifiable issuance, last-success timestamp, source attempt
  success, SHA-256, hash status, freshness basis/age/threshold, bounded cache headers.
- `warnings[]`: `{code, message}`. Do not ignore them even when data is present.
- `error`: null or `{code, message, retryable}`.
- `data`: null on error, otherwise one of the three shapes below.

Null timestamps remain unknown. `retrieved_at` means this adapter call, not an
upstream collection. `last_success_at` is always null: current publisher evidence
cannot independently establish a per-source successful download timestamp.

## Forecast shape and alignment

`generated_at` comes from `head/product/creation-date`. `issued_at` stays null
because these snapshots do not separately establish meteorological issuance.
`source` and `locations` preserve source metadata. The configured request point
is 32.8007,-117.0497; the actual NWS grid point is 32.8,-117.06 in the fixtures.
Both are reported. Source coordinates outside 0.05 degrees of the configured
point fail validation; this tolerance accommodates the NWS grid, not user input.

`layouts` maps each original layout key to its attributes and `intervals[]`:
`{start,end,start_local,end_local,period_name}`. Original timestamps/offsets remain
unchanged; local conversions use America/Los_Angeles. Missing ends stay null;
no ends are inferred. Naive or invalid times retain their text with null local
conversion and an uncertainty warning. DST fall-back hours keep distinct offsets.

`parameters[]` contains `{element,attributes,name,time_layout,values}`. Attributes
retain source units, type and applicable location. **Value i belongs to interval i
in that parameter's layout**, not interval i of another parameter. Count mismatch,
missing layout, or conflicting layout keys is an explicit error.

Values are source lexical strings (e.g. `"0"`, `"0.0150"`, `"81"`), null for nil,
empty or explicit NA/N/A/NULL scalar markers, or nested nodes for conditions,
hazards and other structured values. Nodes are `{tag,attributes,text,children}`.
No floating-point rounding, unit conversion, interpolation, probability-to-amount
conversion or absent-parameter invention is performed. Unknown parameter names
with valid layouts are preserved with their attributes and nested values.

Only forecast data blocks are normalized. `excluded_observation_blocks` records
cached observation blocks deliberately excluded. They are not live observations
and can have ambiguous timestamps. Icons are URLs for traceability, not fetched.
The hourly layout is shared once across all 11 series instead of repeating raw XML.

## Discussion and status shapes

Discussion: `{kind,issued_at,issuance_text,text}`. A unique `<pre>` product must
contain AFDSGX, NWS San Diego attribution and meteorological section headings.
Scripts/styles/navigation are removed; text retains product line breaks,
sections and issuance. Equivalent plain product text is supported. Ambiguous or
missing products fail explicitly. A full dated PDT/PST issuance line is converted
only if its offset agrees with Los Angeles DST and its weekday matches its date.
Unrecognized issuance stays unknown and raises a freshness warning. WMO day/time
alone is not used to guess a month or year.

Status: `{kind,collection_attempt_at,sources[]}`. Each of three weather source
rows contains `{output_path,success,http_status,sha256,last_success_at}`. Missing
rows get unknown fields. School metadata and upstream error bodies are excluded.
The status tool does not fetch forecast bodies and always warns `metadata_only`.

## Freshness, cache consistency, errors

| Setting | Default | Rationale |
| --- | --- | --- |
| `WEATHER_DWML_MAX_AGE_HOURS` | 18 | Conservative warning after three nominal six-hour collection cycles |
| `WEATHER_AFD_MAX_AGE_HOURS` | 12 | Discussion can change within a day; two nominal cycles warrants caution |
| `WEATHER_STATUS_MAX_AGE_HOURS` | 12 | Detect likely missed collection cycles |

Settings are deployment environment variables, finite 1–168 hours. These are
warning policies, not NWS timeliness guarantees. Adjust only with owner review.
A recent document-generation time is weaker evidence than an issuance time.
DWML therefore includes `issuance_unproven` even when within its age threshold.
All forecast validity times in the past adds `forecast_expired`. A future time
more than 15 minutes ahead triggers clock/source uncertainty.

Weather calls fetch the source and then status with `Cache-Control: no-cache`.
They compute SHA-256 over the exact fetched bytes and compare against status.
Matching hashes establish consistency, not freshness; failed attempts can retain
old files and matching hashes. A mismatch returns `publication_inconsistent`,
not a corruption claim. Requests are not atomic; Pages may serve different
publication generations. No automatic retry storm or hidden stale fallback is
used. Retry later when inconsistent. Cross-tool calls can also observe different
generations; compare their attempt/generation timestamps before combining them.

Missing/malformed status still permits explicitly degraded content. Network/HTTP,
HTML-instead-of-DWML, malformed XML, changed AFD markup, oversized responses and
alignment errors return actionable, bounded failures with no substitute forecast.
HTTP 408/429/5xx and network timeouts are retryable. No upstream error body or
exception detail is returned.

Each upstream request has a 3-second connect timeout, 8-second I/O timeout and
12-second total deadline. A weather call makes at most two GETs. Responses are
streamed with a 512 KiB cap; redirects and compressed responses are rejected.
XML entities/DTD are forbidden; depth and element-count limits apply. At most
eight calls fetch concurrently; the local HTTP runner limits connections to 16.
Transport request bodies are capped at 16 KiB. No persistent cache, filesystem
writes, environment proxy forwarding or upstream credentials are used.
Normalized output is capped at 1 MiB (before the compatibility text copy); an
oversized result fails explicitly rather than truncating forecast series. XML
attributes per element are capped at 8 KiB and forecast series at 64 to bound
normalization expansion. The real fixtures are far below these limits.
